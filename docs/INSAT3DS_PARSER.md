# INSAT-3DS HDF5 Parser

## Overview
This module provides a robust, native read-only ingestion parser for INSAT-3DS L1B Standard and L2B Cloud Top Property (CTP) HDF5 files. 

The primary goals of this parser are:
1. **Preserve native grids**: Avoid resampling during extraction to retain raw scientific fidelity (1km VIS/SWIR, 4km IR/WV, native CTP grids).
2. **Handle metadata safely**: Safely extract calibration metadata (`scale_factor`, `add_offset`, `_FillValue`) directly from dataset attributes without hardcoding guesses.
3. **Handle Memory efficiently**: Extract only necessary variables without loading redundant chunks of the ~400MB L1B files into RAM.
4. **Explicit Geolocation mapping**: Map physical data arrays directly to their associated `Latitude` and `Longitude` grids explicitly, ensuring that coordinate mapping remains accurate.

## Native Grids

### L1B Standard 
- **1km Spatial Resolution**: `IMG_VIS`, `IMG_SWIR` (Dimensions: `11264 x 11220`).
- **4km Spatial Resolution**: `IMG_MIR`, `IMG_WV`, `IMG_TIR1`, `IMG_TIR2` (Dimensions: `2816 x 2805`).

### L2B CTP
- **Variable Resolution**: `CTP`, `CTT`, `EFF_EMISS` natively map to a `313 x 312` coarse grid.

## Geolocation

Unlike CF-compliant NetCDF conventions where xarray automatically maps standard dimensions, the INSAT-3DS files rely on HDF5 dimension scale references that `h5netcdf` struggles with natively. 
- The parser explicitly loads `Latitude`, `Longitude` (for 4km and CTP) and `Latitude_VIS`, `Longitude_VIS` (for 1km).
- These are attached to the respective `xarray.DataArray` via `coords`.

## Scaling and Fill Handling

1. **Fill Values**: The `_FillValue` attribute is extracted. Data matching this fill value is replaced with `np.nan` strictly using floating-point types to allow proper missing data downstream.
2. **Scaling**: If a `scale_factor` or `add_offset` attribute exists and differs from `1.0` or `0.0`, the data is calibrated as: `(data * scale_factor) + add_offset`.

## Timestamp Handling

The root attribute `Acquisition_Start_Time` (e.g. `29-MAY-2025T12:00:15.568`) is safely decoded and parsed into a timezone-aware UTC `datetime.datetime`. This timestamp is stamped onto the final `DataPayload` metadata.

## Provenance

Every payload generated by this parser guarantees the following provenance contract:
- `source_name = "MOSDAC"`
- `source_type = "satellite"`
- `is_synthetic = False`
- `file_format = "HDF5"`

## Memory Strategy

The L1B files approach 400MB uncompressed. 
- Files are opened dynamically inside `h5py.File(f, 'r')` context managers.
- Variables are evaluated, loaded into smaller NumPy arrays in memory, cleaned, scaled, and packed into an `xarray.Dataset`.
- `h5py` ensures we never hold the whole file in RAM. Memory scales linearly with the variables chosen.

## Limitations

- The parser strictly operates on the known `INSAT-3DS` file schema. Changes by MOSDAC to dataset paths will trigger a predictable `INSAT3DSParserError`.
- No interpolation is done in this module. Converting the multiple grids (1km, 4km, CTP) into a common domain is the responsibility of the `CommonGridder` stage of the StormFusion pipeline.
