# Part 14 — Multimodal Data Integration

## 1. Supported Modalities
- **Satellite**: Supported natively. Represents the core observations (e.g., INSAT-3DS BTs, Cloud Top Properties).
- **Radar**: Supported via generic gridded data payload or explicitly generated synthetic reflectivity fields.
- **Lightning**: Supported as a collection of flash points mapping to gridded flash density.
- **NWP**: Supported via generic gridded numerical forecasts mapping to environmental features.

## 2. Real vs Synthetic Availability
During Part 14 architecture audit, local directories were inspected to evaluate what genuine files exist:
- **Satellite (INSAT-3DS)**: **REAL** data available (via MOSDAC local manifest).
- **Radar (DWR)**: **NO REAL DATA**. Using `SyntheticDataProvider`.
- **Lightning**: **NO REAL DATA**. Using `SyntheticDataProvider`.
- **NWP/Models**: **NO REAL DATA**. Using `SyntheticDataProvider`.

**Synthetic Data Policy:**
Because radar, lightning, and NWP lack physical data files within the local sandbox, their integration defaults to synthetic generation. Every synthetic product generated by `SyntheticDataProvider` is strictly labeled with:
- `is_synthetic = True`
- `source_name = "Synthetic"`
- Dataset variables encoded with `is_synthetic: True` metadata.

## 3. Data Contracts
The multimodal pipeline defines exactly how to merge different formats:
- `DataPayload`: Standard container for multidimensional `xarray.Dataset` (Radar, Satellite, NWP).
- `LightningDataPayload`: Specialized container for `list[LightningFlash]`.
- `DatasetMetadata`: Unifies attributes across all formats, ensuring all payloads carry timestamps, bounding boxes, resolution, and `nwp_` specialized attributes (e.g., `nwp_init_time`, `nwp_valid_time`).
- `MultimodalSample`: The terminal combination representing the finalized, unified multimodal state at a target analysis time. 

## 4. Temporal Synchronization
Because NWP valid times, radar volume scans, and lightning flash counts occur irregularly:
- Data is passed into a single analysis reference time (e.g., `2025-05-29 12:00:00 UTC`).
- Interpolation is **NOT** used for categorical or sparse variables. We rely strictly on *nearest-time matching* to the analysis target.
- Modalities track a `time_offset_seconds` marking exactly how stale or forward the observation was relative to the common timestamp.

## 5. Spatial Synchronization
The project rigorously enforces the `CommonGridder` constraint verified in Part 13.
- Radar, Lightning, and NWP fields do **NOT** simply resize to arbitrary dimensions.
- They are projected using nearest/Delaunay sampling within a threshold (KD-Tree distance checks) onto the invariant `59 × 58` India Subcontinent bounding box (`8.4°N to 37.6°N` by `68.7°E to 97.2°E`).

## 6. Missing-Data Handling
To maintain scientific validity:
- We **DO NOT** use global 0.0 filling unless a field explicitly measures counts (e.g., Lightning Flash Count). 
- Satellite voids due to missing scans, offshore limits, or clear skies (CTP) explicitly remain `NaN`.
- The `MultimodalSample` tallies exactly how many grid cells fall outside source coverage per modality.

## 7. Provenance Tracking
`MultimodalSample` classifies every synchronized temporal slice with a high-level label:
- **REAL**: Exclusively observational (if, e.g., only satellite loaded).
- **SYNTHETIC**: Exclusively simulated (if running a dummy test).
- **MIXED**: The pipeline detected *both* `is_synthetic=False` (Satellite) and `is_synthetic=True` (NWP/Radar/Lightning) layers in the common grid.
No mixed snapshot can ever be passed off as entirely "Real".

## 8. QC
The generic `QualityController` assesses payloads upstream. Modality statuses inside `MultimodalSample` preserve availability flags natively.

## 9. Six-Timestamp Demonstration
A demonstration script successfully pulled REAL Satellite and SYNTHETIC Radar, Lightning, and NWP through the unified integration architecture across 6 intervals:
- 12:00, 12:30, 13:00, 13:30, 14:00, 14:30
- Total Grid Size: `59 x 58`
- Total Variables combined across modalities.
- Provenance correctly classified as **MIXED**.

## 10. Known Limitations
- Delaunay triangulations for massive variables inside the `CommonGridder` (e.g. `IMG_TIR1` satellite bands) take significant time during execution. Future ML deployments should likely pre-calculate and cache target triangulation masks or employ explicit geospatial reprojection tools like `pyresample` in an operational setting.
- Lightning flash conversion into densities requires careful bounding constraints if scaling dynamically.
